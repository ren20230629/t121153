# XGMC・GM3200 質問応答 ver4.6 修正内容と理由

ver4.5(前処理修正版)からの変更点です。対象は試験項目書の通番27、106、107、108 です。

## 確認状況

- 修正後のコードノード(前処理・資料整理・回答整形)を手元で実行し、下記「修正後の動作」になることを確認しました。検索結果と LLM の出力は模擬データです。
- Dify 上での再試験は未実施です。インポート後に通番27・61・140・104〜111 を再実行して確認してください。
- 変更したのは4ノードだけです。知識検索ノード(ナレッジ6件、Rerank 有効、top_k 8)、分岐、会話変数は ver4.5 と同一です。

| ファイル | 内容 |

## 修正1: 光モジュール同士の比較で、モジュールの仕様書を出典にする(通番27)

### 現象

「H-LX40-SFPとH-LX80-SFPの違いを教えてください」の参照が、`Specification_for_XGMC-2016_SP61-90366AH.pdf p.27`(ナレッジ1)の1件だけになる。

### 原因

ver4.5 のコードで再現しました。

1. XGMC-2016 標準仕様書 p.27 に両方の SFP の値が載っている。資料整理はこのページを「両方の型番を含む資料」として最上位に選ぶ。
2. LLM はこの1ページだけで回答でき、参照もこの1件だけを書く。
3. 回答整形の「型番ごとに出典を補う」処理は、この1件が両方の型番を含むため、補う必要がないと判断する。

### 修正箇所

| ノード | どこを | どう変えたか |
|---|---|---|
| 資料整理 | 関数 `is_module`、`is_device_doc` を追加 | 型番が光モジュールか、資料が装置本体の資料かを判定する。資料名に装置の型番・シリーズ名(XGMC、GMC-、GM3200 など)がある資料を装置の資料とみなす |
| 資料整理 | 候補の並べ替えの直後 | 光モジュール2つ以上の質問で、すべてのモジュールについて装置以外の資料に仕様(伝送特性・主要特性・送信波長・光送信レベル)が検索されていれば、装置の資料を候補から外す |
| 資料整理 | 候補の採点 | 同じ質問で、型番を含み伝送特性の表がある装置以外の資料に 2 点加点する |
| 前処理・入力判定 | `classify_part` の検索語の組み立て | 光モジュール同士の比較で観点の指定が無い質問(「AとBの違い」)の検索語に「標準仕様書 伝送特性 送信波長 光送信レベル 光受信レベル」を加える |

### 理由

- 装置の資料を外すことで、LLM に渡る資料がモジュールの仕様書だけになり、参照もそこから付きます。
- モジュールの仕様が装置の資料にしか検索されなかった場合は、従来どおり装置の資料を使います。回答の値が欠けるのを避けるためです。
- 検索語の追加は、通番61・140(送信波長の比較。両仕様書が参照に出ている)と同じ語を通番27の検索にも入れるものです。

### 修正後の動作

- 参照: `SP61-90362.pdf p.3 ／ H-LX80-SFP仕様書.pdf p.5`
- 試験項目書の全質問で前処理の出力を新旧比較し、検索語が変わるのは通番27だけであることを確認しました。

### 注意点

H-LX40-SFP の仕様書(SP61-90362)の本体は、ナレッジ1の標準仕様書集に収録されています。ナレッジ3にあるのは、SP61-90362 を出典とする検索補助 FAQ です。両方の仕様書がナレッジ3にある組合せで試験したい場合は、質問を次のように変更できます。

> H-LX-SFP-IとH-SX-SFP-Aの違いを教えてください

この質問では、`Specification_for_H-LX-SFP-I_SP61-90779.pdf p.5` と `Specification_for_H-SX-SFP-A_SP61-90778.pdf p.5` が参照になることを手元実行で確認しました。

## 修正2: バージョンの質問で参照が無い場合は「関連記載なし」と答える(通番106・107・108)

### 現象

「〜が追加されたのはどのバージョンですか?」に対し、「明記されていません。関連する記載は次のとおりです」の後に、検索補助 FAQ の「Q. … A. …」の文面やリリースノートの注意書きがそのまま引用される。

### 原因

ver4.3 で回答整形に入れた処理(`related_quote`)が働いていました。バージョンの明記が無いとき、質問の機能名を含む検索結果を 300 字まで引用する処理です。引用元が FAQ のチャンクだと、FAQ の文面がそのまま出ます。

### 修正箇所

| ノード | どこを | どう変えたか |
|---|---|---|
| 回答整形 | 関数 `related_quote` | 削除 |
| 回答整形 | `main` のバージョン質問の処理 | 関連記載の引用と、リリースノートを案内する追記をやめた。バージョンの質問で回答に参照を付けられない場合は、回答を下記の文にする |
| 回答整形 | 同上 | 「どのバージョン」「いつ追加」などを問う質問で、LLM が「明記なし+関連しそうな記載+参照」の形で答えた場合も、同じ文にする |
| 回答整形 | 定数 `NO_RELATED`、`ASK_VERSION_RE`、`VERSION_Q_RE`、`UNSTATED_RE` を追加 | 上記の判定と回答文 |
| 回答生成LLM | システムプロンプトのルール8 | 「明記が無くても関連する記載があれば、その記載内容と参照を示す」を、「バージョン番号が明記されていないときは、関連しそうな記載があってもそれを答えにせず、ルール2の一文だけを答える」に変更 |

回答文:

> 関連記載なし(登録資料に該当する記載が見つかりませんでした。原本のマニュアル・リリースノートを確認してください。)

### 理由

- ご指示の「参照がない場合は 関連記載なし」に合わせました。
- 「バージョンアップ手順書」を含むだけの質問(通番13・26・95・96)は対象外にしています。これらは手順書の内容を聞く質問で、バージョンの質問ではないためです。

### 修正後の動作

| 質問 | ver4.5 | ver4.6 |
|---|---|---|
| 通番106・107・108(追加バージョン。資料に明記なし) | 明記なし+FAQ 文面などの引用 | 関連記載なし(…) |
| 通番109(10G_PKG 対応の追加バージョン。資料に Ver04.02 と明記) | Ver04.02+参照 | 変更なし |
| 通番104(Ver1.05.36 と Ver1.05.49 の違い) | 差分+参照 | 変更なし |
| 通番110・111(削除された機能)で LLM が記載なしと答えた場合 | 記載なし+リリースノートの案内 | 関連記載なし(…) |

### 注意点

通番108 の想定結果は「Ver1.05.11 と返る」です。修正後の回答は「関連記載なし(…)」になるため、想定結果を「記載なし(関連記載なし)と返す。バージョンを創作しない」に変更する必要があります。
